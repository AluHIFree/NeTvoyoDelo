## О проекте

**NeTvoyoDelo** — монолитное веб-приложение на FastAPI с серверным рендерингом (Jinja2) и SQLite. Интерфейс и справка на русском языке.

Платформа рассчитана на подразделения, где входящие документы имеют номера вида `642/07-25`, сроки исполнения, передачи между сотрудниками и отчётность (в том числе для Министерства просвещения России).

| | |
|---|---|
| **Версия** | 1.1.1 |
| **Интерфейс** | Веб-UI (светлая / тёмная тема) |
| **База данных** | SQLite (`correspondences.db`) |
| **Аутентификация** | JWT в HttpOnly-cookie |
| **Лицензия** | MIT |

## Возможности

### Письма и сроки

- Регистрация входящих: номер, даты, отправитель, содержание, срок, исполнитель
- Статусы: **В ожидании** · **В работе** · **Исполнено** · **Просрочено** · **Передано**
- Стадии дедлайна: *Ещё рано* → *Пора начинать* → *Критично* → *Просрочено*
- Автоматический перевод в «Просрочено» (кроме режима «жду внешнего ответа»)
- Флаг **«Жду внешнего ответа»** — письмо не засоряет личную нагрузку и напоминания о просрочке
- Передача коллеге и приём в работу
- Вложения, отправка карточки письма по email
- Связи между письмами: related / reply_to / follow_up / supersedes (внутренние и внешние ссылки, карта связей)
- Сохранённые фильтры и история изменений полей

### Обзор и продуктивность

- Дашборд со статистикой и ближайшими сроками
- **План дня** и todo-лента: просроченные, на сегодня, ближайшие, передачи, непрочитанные
- Панель успеха в профиле: доля исполненных в срок, серия (streak), сравнение с отделом
- AI-отчёт о работе (Cloudflare Workers AI, опционально)

### Потоки, запросы, отчёты

- **Потоки (журналы)** — автоматическая группировка по суффиксу номера после `/` (например, `642/07-25` → поток `07-25`)
- **Письма-запросы**: «Для собственных целей» / «Для Министерства просвещения России»
- Excel-экспорт писем, потоков и запросов (openpyxl, лист с легендой)

### Уведомления

- Браузерный инбокс, email (SMTP), SMS (sms.ru)
- Тихие часы и настройка `reminder_days_before`
- Планировщик APScheduler (расписание часов + ежечасная проверка)

### Администрирование

- Пользователи, блокировка, флаги администратора
- Отделы, KPI-отчёты, журналы доставки уведомлений
- Стартовое создание первого администратора из `.env`
- **Обновления с GitHub** — проверка и установка без потери БД и вложений

## Быстрый старт

### Требования

- Python 3.12+
- pip / venv

### Установка из исходников

```bash
git clone https://github.com/AluHIFree/NeTvoyoDelo.git
cd NeTvoyoDelo

python -m venv venv

# Linux / macOS
source venv/bin/activate

# Windows
# venv\Scripts\activate

pip install -r requirements.txt
```

Создайте файл `.env` в корне проекта (можно взять шаблон из `release/NeTvoyoDelo-Local/.env.example`):

```bash
cp release/NeTvoyoDelo-Local/.env.example .env
```

Отредактируйте как минимум:

- `SECRET_KEY` — длинная случайная строка
- `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `ADMIN_EMAIL`

### Запуск

```bash
python run.py
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000) — режим разработки с `reload=True`.

Альтернативы:

```bash
# Хост и порт из .env, без reload (удобно для «локального» режима)
python run_local.py

# Напрямую через uvicorn
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

Интерактивная OpenAPI-документация: `/docs` и `/redoc`.

## Портативная версия (Windows)

Для пользователей без установленного Python доступна сборка с встроенным интерпретатором.

1. Распакуйте архив `NeTvoyoDelo-Local.zip` в любую папку.
2. Запустите **`START.bat`** — откроется браузер на `http://127.0.0.1:8000`.
3. Остановка: закройте окно или запустите **`STOP.bat`**.

| Параметр | Значение по умолчанию |
|----------|------------------------|
| Логин | `admin` |
| Пароль | `admin123` (смените в `.env`) |
| ОС | Windows 10/11 x64 |
| Сеть | только `127.0.0.1` (извне недоступно) |
| БД | `correspondences.db` рядом с `START.bat` |

В чистой сборке создаётся только администратор; отделы добавляются через панель администратора.

## Конфигурация

Все параметры задаются в `.env` в корне проекта (кодировка `utf-8-sig`). После изменений перезапустите сервер.

| Переменная | Назначение | Пример / по умолчанию |
|------------|------------|------------------------|
| `SECRET_KEY` | Секрет JWT | обязателен |
| `ALGORITHM` | Алгоритм JWT | `HS256` |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Время жизни токена | `30` |
| `PASSWORD_RESET_EXPIRE_MINUTES` | Сброс пароля | `60` |
| `HOST` / `PORT` | Адрес прослушивания | `127.0.0.1` / `8000` |
| `ADMIN_USERNAME` | Первый админ | `admin` |
| `ADMIN_PASSWORD` | Пароль первого админа | — |
| `ADMIN_EMAIL` | Email админа | `admin@example.com` |
| `SEED_DEFAULT_DEPARTMENTS` | Сиды отделов при старте | `true` / `false` |
| `CORS_ORIGINS` | Origins через запятую (без `*`) | `http://127.0.0.1:8000` |
| `PUBLIC_BASE_URL` | Базовый URL в письмах/ссылках | `http://localhost:8000` |
| `SMTP_HOST` / `SMTP_PORT` | SMTP-сервер | `smtp.yandex.ru` / `587` |
| `SMTP_USERNAME` / `SMTP_PASSWORD` | Учётные данные почты | — |
| `SMTP_FROM_EMAIL` / `SMTP_FROM_NAME` | Отправитель | `NeTvoyoDelo` |
| `SMTP_USE_TLS` / `SMTP_USE_SSL` | TLS / SSL | `true` / `false` |
| `SMS_API_URL` / `SMS_API_KEY` | SMS (sms.ru) | — |
| `STALE_LETTER_DAYS` | «Зависшие» письма для контролёров | `7` |
| `NOTIFICATION_SCHEDULE_HOURS` | Часы рассылки | `9,12,16` |
| `CLOUDFLARE_API_KEY` | API key Workers AI | — |
| `CLOUDFLARE_ACCOUNT_ID` | Account ID | — |
| `CLOUDFLARE_MODEL` | Модель | `@cf/meta/llama-3.3-70b-instruct-fp8-fast` |

Поддерживаются алиасы: `SMTP_USER`, `SMTP_FROM`, `SMTP_USE_SSL`.

Для скрипта чистой БД также используется `APP_ROOT` (см. `scripts/prepare_clean_db.py`).

## Роли и доступ

| Роль | Описание |
|------|----------|
| **executor** | Исполнитель — свои письма, передачи, статусы |
| **controller** | Контролёр — письма отдела, «зависшие» документы |
| **viewer** | Наблюдатель — просмотр в рамках отдела |
| **is_admin** | Полный доступ: пользователи, отделы, отчёты, логи |

Доступ к письму: создатель, текущий исполнитель, активная передача; контролёры и viewer видят письма своего отдела; администратор — всё.

## Типовой сценарий

1. Администратор создаёт отделы и пользователей.
2. Сотрудник регистрирует входящее письмо с номером и сроком.
3. Письмо попадает в поток по суффиксу номера (`/07-25` и т.п.).
4. На дашборде появляется задача в плане дня; по стадиям срока приходят уведомления.
5. При необходимости письмо передаётся коллеге или помечается «жду внешнего ответа».
6. После исполнения статус → **Исполнено**; метрики учитываются в панели успеха.
7. Руководитель выгружает Excel или смотрит отчёты в админке.

## Сборка портативного дистрибутива

На машине с Windows и PowerShell:

```powershell
.\scripts\build_portable.ps1
```

Скрипт:

1. Скачивает embeddable Python 3.12.10
2. Устанавливает зависимости из `requirements.txt`
3. Готовит чистую БД (админ без отделов)
4. Собирает каталог `release/NeTvoyoDelo-Local/` и архив `release/NeTvoyoDelo-Local.zip`

Ожидается наличие шаблона `.env.example` в корне репозитория.

## Обновления с GitHub

Администратор открывает раздел **Обновления** в боковом меню:

1. **Проверить обновления** — запрос к GitHub API (релизы или ветка `main`)
2. Просмотр описания изменений (тело релиза или список коммитов / `CHANGELOG.md`)
3. **Установить обновление** — скачивается zipball репозитория и аккуратно накатываются файлы приложения

**Не перезаписываются:**

- `correspondences.db` (и wal/shm)
- `.env`
- `app/static/uploads/`
- `app/static/avatars/`
- `python/` (встроенный интерпретатор portable-сборки)

После установки перезапустите сервис (`STOP.bat` → `START.bat` или остановите `run.py` / `run_local.py` и запустите снова). Лёгкие миграции схемы SQLite выполнятся при старте и не удаляют данные.

Параметры в `.env`:

| Переменная | Назначение |
|------------|------------|
| `GITHUB_REPO` | `AluHIFree/NeTvoyoDelo` |
| `GITHUB_UPDATE_BRANCH` | `main` |
| `GITHUB_TOKEN` | опционально (приватный репо / лимит API) |

## Разработка

### Рекомендации

- Не коммитьте `.env`, `venv/`, `*.db`, содержимое `app/static/uploads/` и `release/`
- Меняйте `SECRET_KEY` и пароль администратора до реального использования
- SMTP, SMS и Cloudflare — опциональны; без ключей соответствующие функции просто неактивны
- Автотесты в репозитории пока не подключены — проверка вручную и через встроенную `/help`

### Чистая база

```bash
python scripts/prepare_clean_db.py

# Для дистрибутива:
# APP_ROOT=/path/to/dist SEED_DEFAULT_DEPARTMENTS=false python scripts/prepare_clean_db.py
```

### Замечания по зависимостям

В `requirements.txt` также указаны `gunicorn` и `psycopg2-binary`; текущий путь приложения — SQLite + Uvicorn. PostgreSQL и Gunicorn в код не встроены.

## Безопасность

- По умолчанию сервер слушает **только localhost** (`127.0.0.1`)
- JWT хранится в HttpOnly-cookie
- CORS без wildcard: явный список origins
- Портативная сборка не предназначена для публикации в открытую сеть без дополнительной защиты (прокси, TLS, смена секретов, бэкапы БД)

Храните и резервируйте:

- `correspondences.db`
- `app/static/uploads/`
- `app/static/avatars/`
